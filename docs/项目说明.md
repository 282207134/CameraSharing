# Camshare 项目结构与架构说明

## 1. 项目概述

Camshare 是用于相机共享租借的 Flutter 移动端演示 App。用户可查看附近相机、浏览规格和样张、查看到店路线、通过相机编号解锁，在归还后查看租借记录；钱包支持添加测试银行卡、充值与优惠码，个人中心支持编辑本地资料。

本次依据 Pixso 当前文件「Page 1」中的 19 张设计图实现。保留设计的英文界面文案，说明文档使用中文。相同页面的输入中、可提交、充值风格等状态由同一组件管理，避免复制整页代码。

## 3. 技术与架构

采用简单的「界面 → 状态与业务 → 本地存储」结构。页面由 Flutter 原生控件构成，原始照片、地图和插画作为本地素材使用。

```text
main.dart
  └─ AppStore.load()                         读取设备中的演示状态
      └─ CamshareApp                        主题与命名路由
          └─ StoreScope                     InheritedNotifier<AppStore>
              └─ feature pages              表单输入、展示与用户操作
                  └─ AppStore               余额、卡片、租借、资料与业务约束
                      └─ SharedPreferencesAsync
                          └─ camshare.v1    JSON 格式的本地演示快照
```

- **页面层**：负责展示、临时输入、校验信息、加载状态、导航；`TextEditingController` 随页面销毁释放。
- **状态层**：`AppStore` 继承 `ChangeNotifier`，集中处理余额与租借状态变更。`StoreScope` 通过 Flutter 自带的 `InheritedNotifier` 分发状态，不增加第三方状态管理框架。
- **数据层**：`Camera` / `Rental` 为明确的数据模型，初始相机与历史记录为设计对应的样本数据。
- **存储层**：通过 `SharedPreferencesAsync` 保存轻量的本地演示快照。页面输入中的完整卡号、CVV 和密码不写入存储。
- **导航**：17 个命名路由由 `app.dart` 统一维护；底部四个主入口切换时清理页面栈，详情页使用 push/pop。

当前业务量较小，未增加空的 repository、service、use-case 包装层。未来接入后端时，可以把 `AppStore` 的持久化及业务方法替换为服务调用，保留页面和模型。

## 6. 核心流程与业务规则

### 租借

1. 点击地图上的相机标记切换相机；点击相机名称查看规格。
2. 点击方向按钮进入路线，选择 `Scan to unlock`。
3. 扫码页面提供示例 QR 与手动编号入口。手动输入满 4 位数字后启用解锁按钮。
4. 余额至少 $4.10，且没有进行中的租借，才可解锁。演示模式接受任意 4 位数字。
5. 解锁后首页显示归还按钮；归还扣除 $4.10，新增历史记录。重复归还不会再次扣款。
6. 进行中的相机也会保存，重启后仍可归还。

### 钱包

- 余额内部以整数分保存，界面统一格式化为美元，避免浮点累计误差。
- 添加卡片执行 Luhn、月份和有效期、CVV 长度检查。仅卡片末四位用于本地展示，重复末四位不重复添加。
- 充值金额为 $20 / 28 / 35 / 42 / 50 / 57 / 64 / 85 / 100。选择金额后进入支付确认；支付成功增加本地演示余额。
- `CAMSHARE1578` 不区分大小写，赠送 $10，只能使用一次。无效或重复使用会给出反馈。
- 保存和支付按钮在执行时禁用，避免重复提交。

### 本地身份与资料

- 注册与登录用于进入本地演示，没有真实账号服务。
- 用户名必填、邮箱校验格式、密码至少 6 位、确认密码必须一致。
- 资料页保存姓名和邮箱；密码字段仅展示表单校验，不保存密码，也不构成真实密码修改。
- Facebook / Google 入口会说明当前使用演示身份，不声称完成 OAuth 登录。

## 7. 设计还原与代码精简

- 主题集中在 `core/theme.dart`，主紫色 `#7B3FFF`、深蓝 `#051C3F`、浅灰 `#F6F7FB`。
- Pixso 返回的首页 Flutter 代码只包含整页图片，未直接作为运行页面使用；实际交互由 Flutter 布局、表单和路由实现。导出结果保留为 `reference/pixso-home-export.txt` 供追溯。
- 地图、相机缩略图、照片合集、品牌图形与成功插画使用从 Pixso 导出的素材，资源全部本地化，无临时 localhost 资源依赖。
- 原稿字体为 Product Sans / Circular Std / Avenir。当前未提供这些字体文件，改用本地打包的开源 DM Sans，因此文字宽度与部分换行会有细微差异。字体来源：[Google Fonts DM Sans](https://github.com/google/fonts/tree/main/ofl/dmsans)，授权见 `assets/fonts/OFL.txt`。
- 共用 `PrimaryButton`、`AppField`、`PageFrame`、`CamNavigation`、`RoundPanel`、`FillScroll`、相机摘要和银行卡组件；欢迎、登录、钱包、扫码和编号页共用填满屏幕并允许滚动的布局。
- 同一页面的多种状态通过参数与局部状态管理，移除生成器的无用辅助文件、Flutter 默认计数器与默认测试，不添加重复状态管理依赖。
- 表单支持键盘弹出时滚动，收起键盘时恢复底部导航；小屏内容可滚动，避免固定尺寸溢出。

## 8. 运行与验证

环境：Flutter 3.41.6 / Dart 3.11.4；本地可运行的 iOS 26.0、iPhone 17 Pro 模拟器。

```sh
flutter pub get
flutter run
```

检查命令：

```sh
flutter analyze
flutter test
flutter build ios --simulator --debug
flutter drive \
  --driver=test_driver/integration_test.dart \
  --target=integration_test/app_test.dart \
  -d <iPhone模拟器设备ID>
```

测试范围：

- 5 项业务与校验测试：优惠码一次性使用、金额精度、租借边界和重复归还、卡片信息最小化保存、卡号与有效期校验。
- 3 项布局测试：375×812、402×874、320×568，逐一构建全部页面并检查 Flutter 布局异常。
- 模拟器完整流程：登录 → 规格 → 相册 → 路线 → 编号解锁 → 归还 → 历史筛选 → 添加卡片 → 充值 → 优惠码 → 资料修改，截图并重新读取本地数据验证恢复。
- 集成测试使用 `camshare.integration.v1` 独立存储键，结束后清理该键；常规 App 使用 `camshare.v1`。

最终执行结果见[验证记录](验证记录.md)。

## 9. 当前交付边界

这是一套能离线运行的 UI 与交互演示。未连接真实 GPS、在线地图路由、摄像头扫码、相机门锁、账号认证、OAuth、支付通道或云端图片服务。页面中的路线、QR 和历史样本来自本地演示数据；不会产生真实扣款或发出通知。

后续对接可从 `AppStore` 入手：把相机列表换成服务端数据、将 `unlock` / `finishRental` 换成设备接口，把充值与银行卡接入支付服务，再由服务端管理余额和订单。`shared_preferences` 仅用于当前演示的简单设备数据，不用于正式金融账本；参考[插件官方文档](https://pub.dev/packages/shared_preferences)。
